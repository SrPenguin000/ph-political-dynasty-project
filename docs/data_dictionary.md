## 1. Database Architecture Overview
The `dynasty_db` PostgreSQL database utilizes a Star Schema architecture. It centers around two primary fact tables (`fact_electoral_membership` and `fact_person_clan`) surrounded by descriptive dimension tables (`dim_person`, `dim_geography`, and `dim_clan`).

## 2. Dimension Tables

### `dim_person`
Stores the standardized identity profiles of elected public officials across all historical datasets. Entity resolution assigns a single ID to a politician over their entire career.
* `person_id` (VARCHAR, PK): Unique identifier for the individual politician.
* `first_name` (VARCHAR): Standardized first name (stripped of titles and suffixes).
* `last_name` (VARCHAR): Standardized family surname.
* `middle_name` (VARCHAR, Nullable): Used by the kinship engine for maternal linkage tracing.
* `suffix` (VARCHAR, Nullable): Generational suffixes (e.g., JR., III).

### `dim_geography`
Standardized location lookup for Philippine municipalities, districts, and provinces.
* `location_id` (VARCHAR, PK): Unique geographic identifier generated via hash.
* `province_std` (VARCHAR): Standardized province name (e.g., "CEBU", "NCR SECOND DISTRICT").
* `town_std` (VARCHAR): Standardized municipality or city. Contains "PROVINCIAL WIDE" for gubernatorial or board member seats.
* `psgc_code` (VARCHAR, Nullable): Philippine Standard Geographic Code mapped from PSA standardizations.

### `dim_clan`
Stores network clusters generated by the kinship engine algorithm. A clan represents a connected component of relatives in public office.
* `clan_id` (VARCHAR, PK): Unique identifier for the familial network component.
* `clan_surname` (VARCHAR): The dominant or root surname identifying the dynasty.
* `n_members` (INTEGER): Represents the **total number of historical election wins** accumulated by the clan (Note: Does not represent unique individual human counts).

## 3. Fact Tables

### `fact_electoral_membership`
The core transactional fact table recording every successful electoral win by a politician.
* `membership_id` (VARCHAR, PK): Unique identifier for the specific election win.
* `person_id` (VARCHAR, FK): Links to `dim_person`.
* `location_id` (VARCHAR, FK): Links to `dim_geography`.
* `year` (INTEGER): The year the politician was elected (1987 to 2025).
* `position` (VARCHAR): Standardized elected role (e.g., MAYOR, GOVERNOR, PROVINCIAL BOARD MEMBER).
* `party` (VARCHAR, Nullable): Electoral party affiliation.
* `source` (VARCHAR): Origin of the data record (`ATENEO_2022`, `HF`, `OPENHALALAN`).

### `fact_person_clan`
A bridging fact table that resolves the many-to-many relationship between individuals and their broader dynastic network. Used to calculate distinct human headcount per dynasty.
* `person_id` (VARCHAR, FK): Links to `dim_person`.
* `clan_id` (VARCHAR, FK): Links to `dim_clan`.

### `fact_poverty_metric`
Socioeconomic covariate data mapped geographically.
* `location_id` (VARCHAR, FK): Links to `dim_geography`.
* `year` (INTEGER): Year of the poverty census (e.g., 2018).
* `poverty_incidence` (FLOAT): Percentage of the local population falling below the poverty threshold[cite: 1, 2, 4].
